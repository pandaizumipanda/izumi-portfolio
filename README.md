# IZUMI FUKUYAMA — Portfolio Site

福山いずみのポートフォリオサイト。フレームワーク不要の静的サイトなので、
ファイルをそのままレンタルサーバーや GitHub Pages にアップロードすれば公開できます。

**編集する場所は2つだけです。**

| 変えたいもの | 編集する場所 |
|---|---|
| **文章・作品情報** | `content.txt`（1ファイル）→ `python3 tools/build_site.py` で反映 |
| **画像** | `images/`（1フォルダ）→ 同じ名前のPNGで上書きするだけ |

---

## 1. ファイル構成

```
IFPF/
├── content.txt         ★ サイトの文章すべて（ここを編集）
├── images/             ★ サイトの画像すべて 26点（ここを差し替え）
│
├── index.html          ↓ ここから下は content.txt から自動生成されます
├── works.html            （直接編集しないでください）
├── event.html
├── about.html
├── contact.html
├── privacy.html
│
├── assets/
│   ├── css/style.css   デザイン（色・余白・レイアウト）
│   └── js/main.js      メニュー開閉・フェードイン・絞り込み・ポップアップ
├── tools/
│   ├── build_site.py       content.txt → HTML の生成
│   ├── gen_placeholders.py プレースホルダー画像の生成
│   ├── shrink_deco.py      背景装飾の表示用（軽量）画像を書き出す
│   ├── dev_server.py       ローカルプレビュー用のサーバー
│   └── font5x7.py          （画像のラベル描画用）
└── .claude/launch.json ローカルプレビュー用の設定
```

## 2. 作業の流れ

```bash
python3 tools/dev_server.py
```

`http://localhost:5173/` を開いたまま、次を繰り返します。

1. `content.txt` を編集して保存
2. 反映する

```bash
python3 tools/build_site.py
```

3. ブラウザを再読み込み（Ctrl + R）

`dev_server.py` はブラウザにキャッシュさせないので、CSSや画像を差し替えても
再読み込みだけで必ず最新の表示になります。

## 3. content.txt の書き方

```
[work]
image: works-01
title: Panda Daily
category: vibe-coding, web, illustration
catch: 笹っと進める、感情表現つきToDoアプリ。
text: タスクの達成率に合わせて、パンダの表情やメッセージが変化するWebアプリ。
text: 単にタスクを管理するだけではなく、進捗に小さなリアクションを加えることで…
role: Planning / UI / Illustration / Vibe Coding
```

- `#` で始まる行はメモ（サイトには出ません）
- `[work]` のように `[ ]` で囲んだ行から、次の `[ ]` までが1つのかたまり
- `項目: 内容` の形式（最初の `:` までが項目名）
- `text:` のように**同じ項目を何度も書くと、その分だけ段落が増えます**
- 長い文は次の行に続けて書けます
- 内容を空にすると、その項目は表示されません（例：`role:` だけ書けば担当範囲は出ません）
- `image:` は `images/` のファイル名（`.png` は省略可）
- 本文にリンクを入れたいときは `[表示する文字](リンク先)`

### かたまりの種類

| 見出し | 内容 |
|---|---|
| `[site]` | サイト名、タグライン、SNSのURL、公開URL |
| `[nav]` `[footer]` | メニュー項目 |
| `[page index]` など | 各ページのタイトル・説明文（検索結果やSNSに出ます） |
| `[hero]` | TOPのキャッチコピーとヒーロー画像 |
| `[works]` `[filter]` | WORKSの見出しと絞り込みボタン |
| `[work]` × 10 | **作品1件ずつ**（並べた順に表示） |
| `[event]` `[program]` × 3 | EVENTの見出しと各プログラム |
| `[about]` `[field]` × 6 | ABOUTの各ブロック |
| `[contact]` | CONTACTの文章と、お問い合わせ種別の選択肢 |
| `[privacy]` | プライバシーポリシー（`h2:` `p:` `li:` を書いた順に表示） |

### よくある編集

**作品を増やす**：`[work]` のかたまりをコピーして貼り付け、内容を書き換える。
画像は `images/works-26.png` を用意（プレースホルダーの作り方は5章）。

**作品の並び順を変える**：`[work]` のかたまりごと上下に移動する。

**TOPに載せる作品を変える**：`[works]` の `pickup:` の並びを変える。

**カテゴリーを増やす**：`[filter]` に `item: 記号 | 表示名 | 説明` を追加し、
各作品の `category:` にその記号を書く。

## 4. 画像の差し替え

`images/` の中の**同じ名前のPNGで上書きするだけ**です。content.txt もHTMLも触りません。

- **縦横比を合わせる**のがきれいに収まるコツです（枠は固定、はみ出た分は中央基準でトリミング）
- 推奨サイズ以上の大きさを入れておくと、高精細ディスプレイでもぼやけません
- `logo.png` と `deco-*.png` は**背景透過PNG**を想定しています
- `works-01〜10.png` は content.txt の `[work]` の並び順と対応しています
  （`works-01` = ご当地ほりにし、`works-05` = Panda Daily、`works-10` = Commission）

| ファイル | 推奨サイズ | 用途 |
|---|---|---|
| `logo.png` | 320×96 | ヘッダー / フッターのロゴ（透過） |
| `favicon.png` | 512×512 | ファビコン / Apple タッチアイコン |
| `og-image.png` | 1200×630 | SNSでシェアされたときの画像 |
| `hero-main.png` | 1400×1050 | TOP ヒーロー メイン (4:3) |
| `hero-sub-01〜03.png` | 600×600 | TOP ヒーロー サブ (1:1) |
| `about-main.png` | 1000×1250 | ABOUT ポートレート (4:5) |
| `works-01〜10.png` | 1000×1000 | WORKS サムネイル (1:1) |
| `event-main.png` | 1200×900 | EVENT 導入ビジュアル (4:3) |
| `event-01〜03.png` | 1200×900 | EVENT 各プログラムの写真 (4:3) |
| `deco-01〜03.png` | 480×480 | （現在は未使用） |
| `images/deco/` の中身 | 自由 | **背景に散りばめる装飾イラスト（透過PNG）** |

### 背景に散りばめる装飾（`images/deco/`）

`images/deco/` に入れた画像が、各ページに自動で散りばめられます。ファイル名は自由
（日本語・スペースもOK）で、**入れる／消すだけで増減**します。

**画像を追加・差し替えたら、この2つを実行してください。**

```bash
python3 tools/shrink_deco.py
```

```bash
python3 tools/build_site.py
```

`shrink_deco.py` は `images/deco-sm/` に表示用の軽い版を書き出します（長辺360pxに縮小
→ 透明な余白を切り落として正方形に整形）。サイトは `deco-sm/` を読み込むので、
**元画像（`images/deco/`）は消してしまっても構いません**。

- **枚数は画面幅で変わります**（最大5枚）

  | 画面幅 | 表示枚数 |
  |---|---|
  | 1200px 超 | 5枚 |
  | 900〜1200px | 4枚 |
  | 700〜900px | 3枚 |
  | 520〜700px | 2枚 |
  | 520px 未満 | 1枚 |

  ページによって置ける場所の数が違うので、上限に届かないページもあります
  （TOP 5 / ABOUT 4 / WORKS・EVENT 3 / CONTACT・PRIVACY 2）。
  上限は `tools/build_site.py` の `DECO_PER_PAGE`、切り替わる幅は
  `assets/css/style.css` の `.deco--i2`〜`.deco--i5` のメディアクエリです。
- **文章・写真には絶対に重なりません**。置き場所は「セクションとセクションの境目」と
  「最後のセクションとフッターの境目」だけで、そこは上下とも余白なので中身がありません。
  大きさもその余白に回転した状態で収まる値（`--deco-size`）を画面幅から計算しています
- **重なり順はいちばん下**。本文・写真（`.wrap`）に `z-index: 1` を付けてあるので、
  装飾（`z-index: 0`）より必ず前面に出ます
- **大きさは全部同じ**（画面幅1440pxで138px、1280pxで126px、375pxで68px）
- **横位置は左・中央・右**をランダムな順で巡回。同じ位置が続けて出ることはありません
- **同じ絵が近くに出ません**（全種類を1巡してから配り直す方式）
- TOPの1枚目だけは決まった絵（`tools/build_site.py` の `HERO_PIN`＝かにだんご）
- 濃さは 0.75（`assets/css/style.css` の `.deco { opacity: ... }`）

## 7. 文字のアニメーション

`assets/css/style.css` の「15. 文字のアニメーション」にまとまっています。
すべて **JavaScript が有効なときだけ** 動き、`prefers-reduced-motion: reduce`
（OS側で「視差効果を減らす」を有効にしている環境）では停止します。

| 種類 | 動き | 付いている場所 |
|---|---|---|
| `.a-up` | 枠で切り取った下から文字が持ち上がる | 見出し（`sec-head__title` / `page-head__catch` / `event__title` / `profile__name` など） |
| `data-anim="chars"` | 1文字ずつ順番に浮かび上がる。カーソルを乗せると波打つ | TOPのキャッチコピー |
| `.a-switch` | カーソルを乗せると文字が上へ抜け、同じ文字が下から入る | ナビゲーション、ボタン、絞り込みボタン |
| `.card__zoom` | カードの画像にカーソルを乗せると「＋」が浮かび上がる | WORKS / EVENT 一覧のカード |
| `.feature` | 写真が少し拡大し、右上に矢印が浮かび上がる | ホームのスライドカード |
| `.scroll-cue` | 縦線が上から下へ伸びて消える（`clip-path`） | ヒーロー下の「Scroll」 |

- `.a-up` は `tools/build_site.py` が見出しを自動で `<span>` で包みます（HTMLを手で書く必要はありません）。
  対象クラスを増やしたいときは同ファイルの `UP_TARGETS` に追記します。
- 1文字ずつの分割は `assets/js/main.js` が行い、読み上げ用に元の文章を `aria-label` に残します。
  文字を増やしたい要素には `data-anim="chars"` を付けてください。
- ホバーの入れ替えも `main.js` が文字を2枚重ねにします（下の1枚は `aria-hidden`）。
- 「Scroll」の文字は `content.txt` の `[hero]` の `scroll_label:` で変更・非表示にできます。
- 動きの速さは `style.css` の各 `transition` / `animation` の秒数を変えてください。

## 8. ホームのWORKS / EVENT（スライドカード）

ホームでは写真タイルを**横スライドするカード列**で見せ、押すと一覧ページの該当項目へ移動します。

```
ホーム                              移動先
スライダー（.slider）               works.html#works-01
├ 写真タイル（.feature）を横並び     └ その作品のポップアップが開いた状態で表示
│  ├ 大きい写真（ホバーで拡大＋矢印）
│  ├ タグ（写真の上に重ねて表示）
│  └ 題名（同上・最大3行）
└ 操作UI（.slider__nav）
   ← ボタン ／ 現在 と 総数 ／ → ボタン
```

- **操作方法**：前後ボタン、マウスでのドラッグ、スマホのスワイプ、
  枠を選んでからの左右キー。末尾で「次へ」を押すと先頭へ戻ります。
- **一度に見せる枚数**は `assets/css/style.css` の `.slider__track` の `--per` で変えられます
  （WORKS は3枚、EVENT は2枚。880px以下・560px以下では自動的に減って次のカードが少し覗きます）。
- カードの間隔は同じ場所の `--slider-gap` です。
- ライブラリは使わず、CSSの `scroll-snap` とブラウザ標準のスクロールで動かしています
  （スマホのスワイプは端末本来の動きのままです）。

- ホームに載せる作品は `content.txt` の `[works]` の `pickup:` で選びます（現在6件）。
  件数を増減してもスライダーの総数表示は自動で合わせます。
- 一覧ページの各カードには `id="works-01"` のような目印が付いていて、
  `works.html#works-01` で開くとその項目のポップアップが自動で開きます。
- EVENTのタイルも同じ仕組みで `event.html#event-01` へ移動します（横長の 4:3）。
- ホームには詳細テキストもポップアップも出力されません（説明文の重複がなくなります）。

## 9. WORKS / EVENT 一覧の詳細ポップアップ

一覧ページのカードは **画像・タグ・題名だけ** を出し、画像を押すと詳細がポップアップで開きます。

```
カード（一覧に出る部分）          ポップアップ（画像を押すと出る部分）
├ 画像（押せる）                  ├ 大きい画像
├ タグ                            ├ タグ
└ 題名                            ├ 題名
                                  ├ catch / text（説明文）
                                  └ role（担当範囲）
                                    EVENTは開催日・会場などの一覧も
```

- `content.txt` の書き方は今までと同じです。`catch:` `text:` `role:`、
  EVENTの `date:` `place:` などが**そのままポップアップの中身**になります。
- 一覧に出す項目を変えたいときは `tools/build_site.py` の `work_card()` / `program_card()` で、
  `card__body`（一覧）と `card__detail`（ポップアップ）のどちらに置くかを入れ替えます。
- ポップアップの本体は各ページ末尾の `<dialog class="modal">` 1つだけで、
  押されたカードの内容を複製して表示します（カードが無いページには出力されません）。
- 閉じ方は「×ボタン」「背景クリック」「`Esc` キー」の3通り。開いている間は
  背面のスクロールを止め、閉じたら元のカードにフォーカスを戻します。
- **JavaScriptが無効な環境では、説明文がカード内にそのまま表示されます**
  （ポップアップが使えない代わりに情報は欠けません）。

## 10. お問い合わせフォームについて

設定は `content.txt` の `[site]` にある次の2行だけです。

```
email: your@example.com     送信先のメールアドレス
form_action:                （空でOK。フォームサービスを使うときだけURLを書く）
```

**A. `form_action:` が空のとき（初期設定・サーバー不要）**

送信ボタンを押すと、入力内容が本文に入った状態で訪問者のメールソフトが立ち上がり、
`email:` 宛のメールが作成されます。あとは訪問者が送信ボタンを押すだけです。
静的サイトのままメールを受け取れる代わりに、訪問者の端末にメールソフトの設定が
必要になります（設定がないと何も起きません）。

**B. `form_action:` にURLを書いたとき（フォームサービス経由）**

Formspree / Google フォーム / サーバー設置のPHP など、送信先のURLを書くと、
フォームはそのURLへ普通に POST します（メールソフトは開きません）。
どのサービスでも、`name` `company` `email` `type` `message` という項目名で届きます。

どちらの場合も、変更後は `python3 tools/build_site.py` で再ビルドしてください。

## 12. 実装メモ

- 依存ライブラリなし。Python は標準ライブラリのみ（生成スクリプト用）。
- 画像は初期表示外のものに `loading="lazy"` を付与。
- フェードインと文字アニメーションは `IntersectionObserver`。JS無効でも本文が消えないよう、
  初期非表示は `<html class="js">` が付いているときのみ適用されます。
  監視が届かない環境向けに、画面内に入っている要素を後から表示する保険も入れています。
- `prefers-reduced-motion: reduce` の環境ではアニメーションを停止します。
- スキップリンク、`Esc` でメニューを閉じる、フォーカスリング、
  `aria-current` / `aria-expanded` / `aria-pressed` に対応。
